# T1059.001 - PowerShell

## The Attack - What Actually Happens
PowerShell is the workhorse execution technique for all three seed
groups, but it shows up doing different jobs. For APT29 in the
SolarWinds/SUNBURST intrusion, Mandiant's UNC2452/APT29 writeup
documents PowerShell (alongside Cobalt Strike loaders) as the execution
vector that got the group from an initial phishing payload to Domain
Administrator in under 12 hours. For APT28, Volexity's 2024 "Nearest
Neighbor Attack" report describes something more specific: a custom
PowerShell script run on an already-compromised system, purpose-built to
enumerate nearby Wi-Fi networks in range - reconnaissance, not payload
delivery. Two different groups, two structurally different uses of the
same technique.

## The Present Problem
"PowerShell was used" is close to a non-signal on its own - it's
present in a huge fraction of intrusions, benign and malicious alike.
The gap isn't detecting PowerShell execution, it's knowing what a given
group's PowerShell usage is *for*, so an analyst can distinguish "this
is credential/lateral-movement staging" from "this is network
reconnaissance for a Wi-Fi pivot" based on which actor's TTPs are in
play, not just the presence of `powershell.exe`.
