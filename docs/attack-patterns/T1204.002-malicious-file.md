# T1204.002 - Malicious File

## The Attack - What Actually Happens
The victim opens the file delivered via T1566.001 and enables content
(macros) or the file exploits a parser bug on open. For APT29's Dukes
malware lineage, F-Secure's "The Dukes" report and the general public
record on the group's tooling (POSHSPY, PowerDuke - documented in
Volexity's "PowerDuke" writeup on the 2016 post-election spearphishing
campaigns) describe the same pattern repeatedly: the weaponized document
exists specifically to launch a PowerShell-based backdoor the moment the
macro runs. The file itself carries no persistence or C2 logic of its
own - it's a one-shot loader.

## The Present Problem
"Malicious file executed" is often the first alert a defender actually
sees (EDR catches the process spawn), but a flat technique catalog
doesn't say what process that file is expected to spawn for a given
actor, so triage starts from zero every time. Knowing in advance that
APT29's malicious-file step causally leads to PowerShell - not, say, a
dropped EXE or a scheduled task - changes what the analyst should hunt
for in the same 60 seconds.

## Cross-Group Comparison
The incoming edge from T1566.001 is where APT29 and Lazarus Group
diverge on mechanism, not just which techniques get used (see
docs/decisions/006-cross-group-comparison.md, comparison `cmp-002`,
confidence 0.7). For APT29, T1204.002 is a local event: the macro is
already inside the delivered attachment. For Lazarus (McAfee's Operation
North Star reporting), the delivered attachment carries no macro at all -
opening it makes Office fetch a remote `.dotm` template hosted under a
`.jpg` extension, and the macro that finally executes lives in that
downloaded template. The chains also diverge immediately downstream:
APT29's macro hands off to a PowerShell backdoor (the outgoing edge
above), while Lazarus's downloaded-template macro loads a DLL via
`rundll32` - a different technique (T1218.011), which is why no mirrored
Lazarus `T1204.002 -> T1059.001` edge is authored here.

## What This Enables
"We confirmed a user ran a macro-enabled document from a suspected
APT29 lure - what's the highest-value next hunt?" resolves to: check for
anomalous PowerShell child processes off Office apps, with the graph
surfacing why that's the first thing to check rather than one option
among many.
