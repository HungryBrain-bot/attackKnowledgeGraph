# T1021.001 - Remote Desktop Protocol

## The Attack - What Actually Happens
Volexity's 2024 "Nearest Neighbor Attack" report documents an unusually
concrete example. APT28 (GruesomeLarch) already held privileged
credentials for an organization ("Organization B") physically near its
real target ("Organization A"). They used those credentials to RDP into
a dual-homed system inside Organization B's own network - not the
target yet, just a pivot point with both a wired connection and a Wi-Fi
radio. Only from that foothold did they run a custom PowerShell script
to enumerate nearby wireless networks and connect to Organization A's
enterprise Wi-Fi. It's lateral movement conducted almost entirely
without traversing the public internet, which is why Volexity gave it a
distinct name rather than filing it as ordinary remote-access abuse.

## The Present Problem
RDP is a legitimate, heavily-used admin tool, so "RDP session observed"
is low-signal by itself. What's missing from a flat lookup is the
*precondition and the consequence*: this incident shows RDP access
required a working credential beforehand (T1078), and that RDP access
was itself what let a further reconnaissance step happen (the
PowerShell Wi-Fi enumeration, T1059.001) - not the reverse. Getting that
direction right matters: a defender who assumes PowerShell recon
precedes RDP access will look for the wrong precondition when triaging
an unexpected RDP session.

## How This Graph Models It

- Edges (both `group_context: APT28`): `T1078 --CAUSALLY_ENABLES-->

## Evidence and Sources
- Volexity, "The Nearest Neighbor Attack: How A Russian APT Weaponized
  Nearby Wi-Fi Networks for Covert Access" (Nov 2024) - the sole source
  for both edges.
- **Correction (2026-08-13):** an earlier pass on this project modeled
  the PowerShell-to-RDP relationship backwards
  (`T1059.001 --CAUSALLY_ENABLES--> T1021.001`), based on an initial,
  partial read of secondary coverage of this report. Fetching and
  reading the full Volexity writeup while sourcing a later edge showed
  the actual sequence is RDP-into-pivot-host first, PowerShell
  enumeration second. The edge, this case file, and T1059.001's case
  file have been corrected accordingly - see `graph/semantic_edges.py`
  for the in-line note on the fixed edge.

## What This Enables
"RDP session detected from an unexpected internal or Wi-Fi-adjacent
host, APT28 suspected - what had to be true beforehand, and what does it
enable next?" resolves to a concrete, correctly-ordered pair: a
compromised credential upstream, and PowerShell-based Wi-Fi
reconnaissance downstream - not the other way around.
